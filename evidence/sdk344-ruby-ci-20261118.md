# Ruby CI origin fix

PR378 CI [44250992331](https://github.com/qubrics/qubrics-sdk/actions/runs/44250992331)
failed four Ruby setup jobs before package tests. GitHub's hosted image was
Ubuntu 26.04, while the pinned official setup action only recognised older
images. Ruby 3.4.1 also has no official Ubuntu 26 binary.

Canonical fix: official [setup-ruby v1.341.0](https://github.com/ruby/setup-ruby/releases/tag/v1.341.0)
at `20eb24b0d509e2b9ed9b6d42ddfeb992915e0564` recognises Ubuntu 26;
[ruby-builder 3.4.12](https://github.com/ruby/ruby-builder/releases/tag/ruby-3.4.12)
provides the matching binary. Vendor [PR974](https://github.com/ruby/setup-ruby/pull/974)
uses these available patches for its own hosted-runner tests.

The operator authorised a separate prerequisite PR, normal green merge and
normal revert rollback. CI and Live E2E use the official immutable action;
the exact Ruby 3.4 test slot, `.ruby-version`, Gemfile and lock entry agree
on 3.4.12. Other Ruby-series slots and all assertions remain intact.
Release, publish and tag workflows are unchanged. No package version or
runtime source changes. The lockfile dependency graph is unchanged.
The native lock entry uses patchlevel 148 from official
[`v3_4_12/version.h`](https://github.com/ruby/ruby/blob/v3_4_12/version.h).
It is aligned directly; no local Ruby 3.4.12 installation is claimed.

Validation: `git diff --check`; exact-head PR CI must pass the four original
setup signals and all 34 CI jobs before merge. Full hosted checks run in CI;
no local copy of the CI suite or new harness. PR378 is refreshed only after
this prerequisite merges. Release workflow Ruby pins remain held outside
this authorised test-workflow slice; publication is still forbidden.

Bulk cause evidence and original failed logs remain in SDK MAIN's local task notes and artifacts while #344
remains open. No tag, upload, publish or environment approval occurred.
